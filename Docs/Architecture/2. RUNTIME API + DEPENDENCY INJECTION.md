# Runtime API + Dependency Injection

## Overview

FlowMapper generates `IMapper<TSource, TDestination>` implementations at compile time. At runtime, these generated mappers are consumed via two APIs:

1. **Direct instantiation** — `new UserMapper().Map(user)`
2. **Dependency Injection** — `IFlowMapper` / `IMapper<,>` resolved from the DI container

## IMapper<TSource, TDestination>

Generated by the source generator for every `[Map<TSource, TDestination>]` declaration:

```csharp
// Declared in FlowMapper.Abstractions
public interface IMapper<in TSource, out TDestination>
{
    TDestination Map(TSource source);
}

// User code:
[Map<User, UserDto>]
public partial class UserMapper;
```

At compile time, the generator produces:

```csharp
// Generated: UserMapper.g.cs
public partial class UserMapper : IMapper<User, UserDto>
{
    public UserDto Map(User source) => new()
    {
        Id = source.Id,
        Name = source.Name,
        Email = source.Email
    };
}
```

## IFlowMapper (DI Dispatch)

For applications using dependency injection, `IFlowMapper` provides a centralized dispatcher:

```csharp
public interface IFlowMapper
{
    TDestination Map<TSource, TDestination>(TSource source);
    IMapper<TSource, TDestination> GetMapper<TSource, TDestination>();
}
```

`FlowMapperService` is the default implementation. It resolves `IMapper<TSource, TDestination>` from the `IServiceProvider`, which is populated by assembly scanning during `AddFlowMapper()`.

## Registration

```csharp
// Program.cs
builder.Services.AddFlowMapper(cfg =>
{
    cfg.DefaultProfile = "Api";
    cfg.EnableFlatten = true;
    cfg.Strictness = StrictnessLevel.Warning;
});
```

`AddFlowMapper()` performs three tasks:

1. Registers `FlowMapperOptions` as a singleton (with defaults or user overrides)
2. Registers `IFlowMapper` as a scoped service (backed by `FlowMapperService`)
3. Scans all loaded assemblies for types implementing `IMapper<,>` and registers them as transient services

## Usage

```csharp
// Option 1: Direct constructor injection of the generated mapper
public class UserService(IMapper<User, UserDto> mapper)
{
    public UserDto Get(int id) => mapper.Map(_repository.Get(id));
}

// Option 2: IFlowMapper dispatch (resolves mapper internally)
public class UserController(IFlowMapper mapper)
{
    public UserDto Get(int id) => mapper.Map<User, UserDto>(_repository.Get(id));
}
```

Option 1 is the most performant — the `IMapper<,>` is resolved once at construction time.

Option 2 is more flexible — useful when the mapper type is determined dynamically.

## Generated Code Location

All generated `.g.cs` files are produced at compile time and placed in the intermediate output directory (`obj/`). They follow the naming convention `{MapperName}.g.cs` or, when using profiles, `{ProfileName}.{MapperName}.g.cs`.

Generated files are compiled as regular source files and produce real IL — there is no reflection, expression tree compilation, or runtime code generation involved.

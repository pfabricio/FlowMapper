### 📄 7. BENCHMARK CLASS BASE

```csharp
using BenchmarkDotNet.Attributes;
using AutoMapper;

public class MappingBenchmark
{
    private IMapper _autoMapper;
    private User _user;
    private UserMapper _flowMapper;

    [GlobalSetup]
    public void Setup()
    {
        var config = new MapperConfiguration(cfg =>
        {
            cfg.CreateMap<User, UserDto>();
        });

        _autoMapper = config.CreateMapper();

        _flowMapper = new UserMapper();

        _user = new User
        {
            Id = 1,
            Name = "Paulo",
            Address = new Address
            {
                City = new City { Name = "Belém" }
            }
        };
    }
}
```

### ⚡ 12. EXPECTATIVA REAL DE RESULTADO

### FlowMapper tende a ganhar em:

-   ✔ runtime speed (code gen vs reflection)
-   ✔ allocation (zero expression trees)
-   ✔ deterministic execution

----------

### AutoMapper tende a perder em:

-   reflection overhead
-   expression tree compilation
-   runtime mapping cost

----------

### 🧠 13. CRITÉRIO DE COMPARAÇÃO JUSTO

Para ser honesto tecnicamente:

-   AutoMapper = runtime dynamic mapping
-   FlowMapper = compile-time generated code

👉 comparação correta é:

> runtime execution cost vs runtime execution cost (ignoring build-time advantage)

----------

### 🚨 14. ALERTA IMPORTANTE (HONESTIDADE TÉCNICA)

O FlowMapper também tem custo:

-   build-time Roslyn generation
-   compilation overhead

Mas:

> isso não impacta runtime production
